# LimeCraft — минималистичный лаунчер Minecraft

**LimeCraft** — десктоп-лаунчер Minecraft в стиле минимализм, выдержанный в
светло-зелёно-жёлтых тонах. Пишется на **Rust** с UI на **eframe/egui**
(нативные элементы, без Electron и браузерного рантайма).

Launcher позволяет выбрать версию, поставить сборку или мод прямо с Modrinth и
запустить игру — всё в одном простом и спокойном интерфейсе.

> Имя LimeCraft утверждено; за образ архитектуры и фич отвечает
> [PLAN.md](PLAN.md), за генерацию картинок — [ASSET_PROMPT.md](ASSET_PROMPT.md).

## Возможности

- **Версии (vanilla)** — список релизов и снапшотов из официального манифеста
  Mojang (`launchermeta.mojang.com`); выбор версии → скачивание `version.json`,
  jar-файла, библиотек и ресурсов с прогрессом и проверкой SHA-1.
- **Сборки (Modrinth)** — поиск модпаков через Modrinth API (v2), карточка
  модпака (иконка, описание, автор, версии, лоадеры), установка `.mrpack`
  с разворачиванием `overrides` и установкой зависимостей (fabric-loader,
  neoforge, forge, minecraft).
- **Моды** — поиск отдельных модов по Modrinth, выбор версии, совместимой
  с лоадером и MC инстанса, скачивание primary-файлов + автоподстановка
  зависимостей, всё складывается в `<инстанс>/mods/`.
- **Лоадеры** — создание модовых профилей с выбором лоадера:
  **Fabric / Quilt** — через свой meta API, **Forge / NeoForge** — через
  официальный installer (скачивается `-installer.jar`, из него берётся профиль
  `version.json`, ставятся библиотеки и json версии).
- **Аккаунт** — выбор способа входа в «Настройках»: **Офлайн** (ник +
  детерминированный UUID v3 по алгоритму Minecraft) или **Microsoft**
  (заготовка, полный OAuth появится позже).
- **Запуск** — сборка classpath из libraries + client.jar, автоматический
  поиск Java (JAVA_HOME, `which`, типовые пути Windows) и спавн процесса
  игры. Офлайн-режим без входа в аккаунт (бесплатная версия).

## Сборка и запуск

Требуется [Rust](https://rustup.rs/) (стабильный тулчейн, edition 2024).

> **Windows: если сборка падает на линковке** (`lld: unable to find library
> -lgcc_eh` / `-lgcc`) — на машине стоит два mingw (LLVM-MinGW и WinLibs), и
> cargo берёт не тот. Поместите **WinLibs mingw64/bin** первым в `PATH`, затем
> соберите заново:
> `$env:PATH = "C:\Users\<you>\AppData\Local\Microsoft\WinGet\Packages\BrechtSanders.WinLibs.POSIX.UCRT_Microsoft.Winget.Source_8wekyb3d8bbwe\mingw64\bin;" + $env:PATH`

```bash
# Отладка
cargo build
cargo run

# Релизная сборка (оптимизирована в Cargo.toml: opt-level = 2)
cargo build --release
cargo run --release
```

### Быстрый старт на Windows

**Самый надёжный способ — `start.cmd`** (двойной клик): он сам снимает блокировку
ExecutionPolicy и вызывает `start.ps1`. Просто откройте папку с лаунчером и
дважды кликните `start.cmd`.

Иначе — `start.ps1` из PowerShell:

```powershell
cd 'C:\tinSundew\minecraft launcher'
.\start.ps1
```

`start.ps1` сам найдёт свою папку (`$PSScriptRoot`), добавит `%USERPROFILE%\.cargo\bin`
и WinLibs mingw64 в `PATH`, затем выполнит `cargo run --release`.

### «Не запускается start.ps1» — что делать

Чаще всего дело в политике выполнения или кодировке, а не в лаунчере:

1. **Политика ExecutionPolicy блокирует .ps1** — запустите так:
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File 'C:\tinSundew\minecraft launcher\start.ps1'
   ```
   (это же делает `start.cmd` автоматически). Разрешить навсегда для текущего
   пользователя: `Set-ExecutionPolicy -Scope CurrentUser Bypass` (в PowerShell
   **от администратора**).
2. **Двойной клик по .ps1 открывает блокнот / ничего не делает** — так работает
   Windows по умолчанию (`.ps1` не ассоциированы с запуском). Пользуйтесь
   `start.cmd` или правым кликом → «Выполнить с помощью PowerShell».
3. **Ошибки про кодировку/русские буквы** в старых версиях скрипта — во избежание
   этого `start.ps1` использует только ASCII-комментарии; синтаксис проверен.
4. **Чёрное окно мигнуло и закрылось** — запустите `start.ps1` из окна PowerShell
   (не двойным кликом), чтобы увидеть текст ошибки. Или выполните вручную:
   `cargo build --release` после добавления WinLibs в PATH (см. предупреждение выше).
5. **Главное окно лаунчера не открывается** при первом запуске — играм нужен
   рабочий стол/GPU; в терминале/по RDP без десктопа окно может не появиться.
   Проверьте на обычной локальной сессии с окном.

## Что внутри src/

Логика отделена от представления: всё сетевое и файловое «железо» живёт
в `src/core/` (без зависимости от UI), а egui-часть — в корне `src/`.

| Файл | Назначение |
|---|---|
| `src/main.rs` | Точка входа приложения. |
| `src/theme.rs` | Палитра (`BG`, `GREEN`, `YELLOW`, `TEXT` и др.) и настройка `Visuals`/`Style` для egui: радиусы, тени, цвета виджетов. |
| `src/assets.rs` | Декодирование встроенных изображений (`include_bytes!`) в egui-текстуры, cover-fit-отрисовка; при ошибке — безопасный фолбэк. |
| `src/core/mod.rs` | Модуль-агрегатор: `download`, `install`, `instance`, `launch`, `mojang`, `modrinth`. |
| `src/core/mojang.rs` | Манифест версий Mojang, модель `version.json`, предметные типы для сборки запуска. |
| `src/core/modrinth.rs` | Клиент Modrinth API v2: поиск, проекты, версии, файлы, хэши, `.mrpack`. |
| `src/core/install.rs` | Установка: vanilla-версии, модовых версий (лоадеры: Fabric/Quilt/Forge/NeoForge), `.mrpack`-сборок с зависимостями; прогресс и отмена. |
| `src/core/account.rs` | Учётная запись: провайдер (Offline/Microsoft), ник, офлайн-UUID v3, токены. |
| `src/core/instance.rs` | Модель инстанса/состояния лаунчера, сохранение в `launcher_state.json`, пути к папкам инстансов. |
| `src/core/launch.rs` | Поиск Java и запуск игры: сборка classpath, аргументы, спавн процесса. |
| `src/core/download.rs` | Загрузка одного файла с прогрессом (атомарные счётчики), проверка SHA-1, ретраи. |

> Сборка UI (экраны, навигация, карточки) подключается к `src/core/` и не
> должна дублировать сетевую/файловую логику.
