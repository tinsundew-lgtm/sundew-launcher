# LimeCraft — минималистичный лаунчер Minecraft

**LimeCraft** — десктоп-лаунчер Minecraft в стиле минимализм, выдержанный в
светло-зелёно-жёлтых тонах. Пишется на **Rust** с UI на **eframe/egui**
(нативные элементы, без Electron и браузерного рантайма).

**Версия 1.0.0** — см. [CHANGELOG.md](CHANGELOG.md).

Launcher позволяет выбрать версию, поставить сборку или мод прямо с Modrinth и
запустить игру — всё в одном простом и спокойном интерфейсе.

> Имя LimeCraft утверждено; за образ архитектуры и фич отвечает
> [PLAN.md](PLAN.md), за генерацию картинок — [ASSET_PROMPT.md](ASSET_PROMPT.md).

## Возможности

- **Версии (vanilla)** — список релизов и снапшотов из официального манифеста
  Mojang; установка клиента, библиотек и ассетов (ассеты качаются параллельно)
  с прогрессом, проверкой SHA-1, таймаутами, повторами и отменой.
- **Сборки (Modrinth)** — поиск модпаков через Modrinth API (v2) и установка
  `.mrpack`: хэши файлов проверяются, серверные файлы (`env`) пропускаются,
  применяются `overrides` и `client-overrides`, ставится нужный загрузчик
  нужной версии. Пути из архива проверяются на выход за пределы инстанса.
- **Моды, ресурспаки, шейдеры** — поиск на Modrinth с фильтром совместимости
  (версия игры и загрузчик сборки; без запроса показываются популярные),
  установка с обязательными зависимостями. Вкладка «Установленные»: список
  с названиями (файлы опознаются по хэшу), включение и выключение
  (`.jar.disabled`), удаление, проверка и установка обновлений.
- **Скины для офлайна** (вкладка «Скины»): библиотека PNG-скинов (64×64 или
  старые 64×32), плоский предпросмотр спереди и сзади (с поддержкой тонких рук
  и внешних слоёв), смена скина одним щелчком, свой скин у каждого профиля.
  Скин можно загрузить из файла или скачать по нику с серверов Mojang (публичные
  данные, вход не нужен; адрес картинки проверяется, принимается только
  `textures.minecraft.net`). Ваниль в офлайне чужие скины не показывает, поэтому
  при запуске лаунчер кладёт выбранный скин в `CustomSkinLoader/LocalSkin/skins/<ник>.png`
  сборки — оттуда его читает мод CustomSkinLoader (Fabric, Forge, NeoForge, Quilt).
  Вкладка показывает, стоит ли мод в выбранной сборке, и ведёт в каталог за ним.
  Голова скина также используется как аватар профиля, если своей картинки нет.
- **Импорт сборок** («Новая сборка» → вкладки):
  - *Из папки* — любая папка с игрой (`.minecraft`, папка сборки из другого
    лаунчера): копируются моды, настройки, ресурспаки, шейдеры, `options.txt`,
    `servers.dat` и по желанию миры; игру и загрузчик лаунчер ставит сам;
  - *Из файла* — сборка Modrinth (`.mrpack`) или экспорт Prism / MultiMC
    (`.zip`); файл можно перетащить в окно. Архив проверяется на небезопасные
    пути и размер, файлы внутри `.mrpack` проверяются по хэшам.
    Сборки CurseForge (`.zip` с `manifest.json`) не поддерживаются: для скачивания
    их модов нужен ключ CurseForge API;
  - *Из лаунчеров* — лаунчер сам находит сборки Prism Launcher, PolyMC
    (с версией и загрузчиком), CurseForge, Modrinth App и `.minecraft`
    официального лаунчера (у двух последних версию выбирает пользователь).
    Исходные файлы не меняются: всё копируется.
- **Иконки** — у модов, модпаков и установленных файлов показываются иконки
  с Modrinth (PNG, JPEG, WebP, GIF). Они качаются в фоне, не больше шести
  одновременно, и кэшируются миниатюрами в `cache/icons` папки данных.
  Пока иконка грузится или её нет, видна цветная плитка с инициалами.
  Сборка из модпака получает иконку модпака.
- **Загрузчики** — **Fabric / Quilt** через их meta API, **Forge / NeoForge**
  запуском официального installer (`--installClient`). Живым запуском
  Forge/NeoForge пока не проверялись.
- **Аккаунт** — офлайн, по нику (3–16 символов: латиница, цифры, `_`).
  UUID вычисляется из ника так же, как это делает Minecraft. Работают
  одиночная игра, LAN и серверы с `online-mode=false`; серверы с проверкой
  лицензии такой аккаунт не пустят. Входа через Microsoft нет.
  Можно завести несколько профилей (ников) со своими аватарами и переключать
  их кнопкой профиля справа вверху на главной; у сборки может быть свой ник.
- **Анимации:** плавное появление страниц и карточек по очереди, скользящий индикатор
  вкладок, кнопки с откликом на нажатие, плавные уведомления, живая фигурка и искры в
  «Скинах». При прокрутке настроек край страницы рассыпается пиксельными блоками,
  песчинки срываются с него и разлетаются по ветру. Пока страница стоит (например, вы
  упёрлись в верх или низ), эффекта нет. «Настройки → Оформление»:
  «Анимации интерфейса» отключает всё движение, «Песок при прокрутке настроек» — только песок.
- **Стиль** («Настройки → Оформление → Стиль»): «Пиксельный» по умолчанию —
  тёмная палитра почти чёрных серых тонов, кнопки и карточки со срезанными углами,
  нажимающиеся «клавиши» с тенью снизу, крупные карточки-обложки сборок, навигация
  сверху (при узком окне подписи сменяются значками). «Мягкий» — прежние
  скруглённые плоские виджеты. Оформление вдохновлено лаунчером Millida Launcher;
  его код, значки, картинки и название не используются.
- **Кастомизация** («Настройки → Оформление» и «Поведение»):
  - цвет акцента (8 готовых, любой свой или «Радуга» — цвет плавно проходит
    все оттенки), тёмная, светлая или системная тема;
  - фон окна: однотонный, градиент или своя картинка; для картинки лаунчер
    измеряет её среднюю яркость и сам выбирает светлый или тёмный текст
    (отключается галочкой «Подбирать цвет текста под фон»);
  - масштаб интерфейса, компактный режим, шрифт (встроенный Manrope, системный
    или стандартный egui);
  - библиотека сеткой или списком, размер карточек, сортировка, группы и
    закреплённые сборки;
  - у сборки своя иконка (картинка с диска) или цвет плитки;
  - окно игры (размер, полноэкранный режим), действие после запуска
    (ничего, свернуть или закрыть лаунчер), пресеты памяти
    («Слабый ПК», «Стандарт», «Много модов»).
- **Сеть** — «Настройки → Проверить сеть» показывает, какие серверы доступны.
  Если основной сервер недоступен, лаунчер сам переходит на зеркала
  (BMCLAPI для Fabric/Forge/NeoForge, MCIM для Modrinth); это отключается
  там же.
- **Запуск** — профиль загрузчика сливается с родительской версией
  (`inheritsFrom`), classpath строится по списку библиотек, аргументы
  разбираются с учётом правил ОС. Java подбирается по требуемой версии
  (`javaVersion`), либо берётся путь из настроек; если подходящей Java нет, лаунчер
  скачивает её сам (Adoptium, с проверкой SHA-256). Вывод игры пишется в
  `launcher.log` в папке инстанса и виден вживую на вкладке «Журнал»
  страницы сборки. Natives (LWJGL) подбираются под процессор и кладутся в
  `natives`; у игры своя папка `tmp`, поэтому закрытая системная Temp не мешает.

Что не сделано, смотрите в разделе 6 [PLAN.md](PLAN.md).

## Проверка скачиваемого

| Что скачивается | Проверка |
|---|---|
| JSON версий, клиент, библиотеки, ассеты Mojang | SHA-1 из манифеста Mojang |
| Библиотеки Fabric/Quilt | SHA-1 из профиля загрузчика (если указан) |
| Установщик Forge/NeoForge | SHA-1 из репозитория (`.sha1`), без суммы установка не начнётся |
| Java (Adoptium) | SHA-256 из API Adoptium |
| Моды, ресурспаки, шейдеры | SHA-1 из API Modrinth |
| Архив модпака `.mrpack` | SHA-1 и SHA-512 из API Modrinth |
| Файлы внутри модпака | SHA-1 и SHA-512, только разрешённые хосты, защита от выхода из папки, лимит размера |
| Иконки проектов Modrinth | Хэша нет (картинка только показывается): лимит 5 МБ, файл должен разобраться как изображение, хранится пересжатая миниатюра PNG |

Всё идёт по HTTPS. Хэш защищает от повреждения и подмены файла по дороге, но
не от вредоносного мода, опубликованного самим автором: проверку содержимого
делает Modrinth. Если основной сервер недоступен и используется зеркало,
хэши приходят от зеркала; зеркала можно отключить в «Настройки → Сеть».

## Сборка и запуск

Требуется [Rust](https://rustup.rs/) (стабильный тулчейн, edition 2024).

> **Windows: если сборка падает на линковке** (`lld: unable to find library
> -lgcc_eh` / `-lgcc`) — на машине стоит два mingw (LLVM-MinGW и WinLibs), и
> cargo берёт не тот. Поместите **WinLibs mingw64/bin** первым в `PATH`, затем
> соберите заново:
> `$env:PATH = "C:\Users\<you>\AppData\Local\Microsoft\WinGet\Packages\BrechtSanders.WinLibs.POSIX.UCRT_Microsoft.Winget.Source_8wekyb3d8bbwe\mingw64\bin;" + $env:PATH`

```bash
# Отладка
cargo build
cargo run

# Тесты (ядро + интерфейс без окна, с поддельными серверами).
# На Windows с GNU-тулчейном запускайте в release: отладочный тестовый exe падает при старте.
cargo test --release

# Релизная сборка (оптимизирована в Cargo.toml: opt-level = 2, lto, strip)
cargo build --release
cargo run --release
```

### Быстрый старт на Windows

**Самый надёжный способ — `start.cmd`** (двойной клик): он сам снимает блокировку
ExecutionPolicy и вызывает `start.ps1`. Просто откройте папку с лаунчером и
дважды кликните `start.cmd`.

Иначе — `start.ps1` из PowerShell:

```powershell
cd 'C:\Users\<you>\Documents\progects\imecraft'
.\start.ps1
```

`start.ps1` сам найдёт свою папку (`$PSScriptRoot`), добавит `%USERPROFILE%\.cargo\bin`
и WinLibs mingw64 в `PATH`, затем выполнит `cargo run --release`.

### «Не запускается start.ps1» — что делать

Чаще всего дело в политике выполнения или кодировке, а не в лаунчере:

1. **Политика ExecutionPolicy блокирует .ps1** — запустите так:
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File 'C:\Users\<you>\Documents\progects\imecraft\start.ps1'
   ```
   (это же делает `start.cmd` автоматически). Разрешить навсегда для текущего
   пользователя: `Set-ExecutionPolicy -Scope CurrentUser Bypass` (в PowerShell
   **от администратора**).
2. **Двойной клик по .ps1 открывает блокнот / ничего не делает** — так работает
   Windows по умолчанию (`.ps1` не ассоциированы с запуском). Пользуйтесь
   `start.cmd` или правым кликом → «Выполнить с помощью PowerShell».
3. **Ошибки про кодировку/русские буквы** в старых версиях скрипта — во избежание
   этого `start.ps1` использует только ASCII-комментарии; синтаксис проверен.
4. **Чёрное окно мигнуло и закрылось** — запустите `start.ps1` из окна PowerShell
   (не двойным кликом), чтобы увидеть текст ошибки. Или выполните вручную:
   `cargo build --release` после добавления WinLibs в PATH (см. предупреждение выше).
5. **Главное окно лаунчера не открывается** при первом запуске — играм нужен
   рабочий стол/GPU; в терминале/по RDP без десктопа окно может не появиться.
   Проверьте на обычной локальной сессии с окном.

## Что внутри src/

Логика отделена от представления: всё сетевое и файловое «железо» живёт
в `src/core/` (без зависимости от UI), а egui-часть — в корне `src/`.

| Файл | Назначение |
|---|---|
| `src/main.rs` | Точка входа: иконка окна, panic-хук (лог в папку данных лаунчера). |
| `src/app.rs` | Весь интерфейс на egui: вкладки «Сборки», «Моды», «Другое», диалоги, фоновые задачи. |
| `src/fx.rs` | Движение: плавность, общий выключатель анимаций, частицы песка с простой физикой. |
| `src/theme.rs` | Палитра во время работы (`bg()`, `card()`, `green()`, `text()` и др.): тёмная или светлая, с выбранным акцентом; масштаб и плотность `Visuals`/`Style` для egui. |
| `src/ui.rs` | Набор виджетов: значки из шрифта Phosphor (`Icon`), «клавиши» со срезанными углами, вкладки, карточки, плитки с инициалами, картинки-иконки. |
| `src/assets.rs` | Декодирование встроенных изображений (`include_bytes!`) в egui-текстуры, cover-fit-отрисовка; при ошибке — безопасный фолбэк. |
| `src/core/mod.rs` | Модуль-агрегатор: `account`, `download`, `images`, `install`, `instance`, `launch`, `modrinth`, `mods`, `mojang`, `import`, `netcheck`, `prefs`, `skins`. |
| `src/core/prefs.rs` | Настройки оформления и поведения: тема, акцент, фон, масштаб, шрифт, вид библиотеки, окно игры, действие после запуска, пресеты памяти. |
| `src/core/skins.rs` | Библиотека скинов: проверка PNG, скачивание по нику, копия в папку мода CustomSkinLoader, геометрия предпросмотра. |
| `src/core/import.rs` | Импорт сборок: из папки, из `.mrpack` / Prism-архива, поиск сборок в других лаунчерах. |
| `src/core/images.rs` | Картинки: иконки сборок и аватары (квадрат), фон окна, иконки Modrinth с кэшем миниатюр. |
| `src/core/mojang.rs` | Манифест версий Mojang, модель `version.json`, предметные типы для сборки запуска. |
| `src/core/modrinth.rs` | Клиент Modrinth API v2: поиск с фильтрами, проекты, версии, опознание по хэшам, `.mrpack`. |
| `src/core/netcheck.rs` | Проверка доступности всех серверов лаунчера. |
| `src/core/mods.rs` | Моды, ресурспаки и шейдеры инстанса: список, включение/выключение, удаление, обновления, план зависимостей. |
| `src/core/install.rs` | Установка vanilla, загрузчиков (Fabric/Quilt/Forge/NeoForge), `.mrpack`-сборок и модов; прогресс и отмена. |
| `src/core/account.rs` | Офлайн-профили: ник, аватар, проверка ника, офлайн-UUID v3. |
| `src/core/instance.rs` | Модель инстанса (иконка, цвет, группа, ник) и состояния лаунчера (профили, настройки), сохранение в `launcher_state.json`, пути к папкам инстансов. |
| `src/core/launch.rs` | Выбор Java по версии, слияние `inheritsFrom`, classpath, аргументы с правилами, запуск и лог. |
| `src/core/download.rs` | Загрузка файла: таймауты, 3 попытки, проверка SHA-1, отмена, запись через `.part`. |

> Сборка UI (экраны, навигация, карточки) подключается к `src/core/` и не
> должна дублировать сетевую/файловую логику.
