# План: «LimeCraft Launcher» — минималистичный лаунчер Minecraft

> **Статус: РЕАЛИЗОВАН + ДОРАБОТАН** (запрос «продолжим?»). Имя —
> **LimeCraft**. Код на Rust/eframe написан: экраны (главный, версии, сборки,
> моды, настройки), установка vanilla / Fabric / Quilt / **Forge / NeoForge**
> в `instances/<name>/mines/` с SHA-1 (Forge/NeoForge — через официальные
> installer-джары), `.mrpack`-сборки с зависимостями и overrides, моды
> с зависимостями, запуск с автопоиском Java. Добавлена учётная запись:
> **офлайн** (ник + UUID v3) полностью, **Microsoft** — заготовка (провайдер
> в модели + выбор в UI, полный OAuth запланирован).

## 1. Идея и назначение

Лаунчер Minecraft в стиле минимализм, выдержанный в светло‑зелёно‑жёлтых
тонах. Позволяет:

- выбирать версию vanilla (релизы и снапшоты из официального манифеста Mojang);
- скачивать и устанавливать сборки (модпаки) прямо с Modrinth;
- ставить модифицированные версии (Fabric / Forge / Quilt/NeoForge);
- скачивать отдельные моды с лаунчера (запрос к Modrinth, авто‑подстановка
  зависимостей) и класть их в нужную папку инстанса.

## 2. Технологический стек

- **Electron** (главный процесс — Node.js, рендер — HTML/CSS/JS): самый
  подходящий формат для десктоп‑лаунчера с современным минимальным UI.
- Бандл Node уже доступен через `load_workspace_dependencies`; Electron
  устанавливается через pnpm (`electron`), его бинарник качается один раз.
- Никакого тяжёлого фреймворка для UI: ванильный HTML/CSS/JS + лёгкий
  синтаксис JS-модулей; минимализм = плоский дизайн, много воздуха, аккуратные
  карточки.
- HTTP-сеть в главном процессе: `net.fetch` либо Node `https`, т.к. fetch в
  песочнице не может достучаться до api.modrinth.com — на реальной машине это
  работает, и пользователю никаких настроек не требуется.

## 3. Возможности (MVP → полный набор)

### 3.1. Главный экран
- Большая кнопка «Играть».
- Приветствие и текущий выбранный профиль/версия.
- Индикатор прогресса скачивания.

### 3.2. Версии (vanilla)
- Манифест `https://launchermeta.mojang.com/mc/game/version_manifest_v2.json`.
- Список релизов и снапшотов; выбор версии → при необходимости
  скачивание `version.json`, jar, библиотек и ресурсов.
- Прогресс-бар, отмена в любой момент.

### 3.3. Сборки (Modrinth)
- Поиск модпаков по Faceted Search API.
- Карточка модпака: иконка/скриншот, описание, автор, версии и лоадеры.
- «Установить» → качаем `.mrpack`, парсим `modrinth.index.json`:
  - разворачиваем `overrides` (карта/конфиги) в инстанс;
  - скачиваем файлы по sha1/sha512 из `files`;
  - ставим зависимости `fabric-loader`, `neoforge`, `forge`, `minecraft` —
    в том числе через Fabric Meta / NeoForge meta (реальный запуск требует
    клиентские файлы; делаем полноценную установку, как Prism).

### 3.4. Мод-инстанс (установка модовых версий)
- Создание профиля: имя + версия Minecraft + лоадер (None/Fabric/Quilt/Forge/NeoForge).
- Для Fabric/Quilt — упрощённая установка через Meta API
  `https://meta.fabricmc.net/v2/versions/loader/...` (для Quilt — свой
  `meta.quiltmc.org`); для Forge/NeoForge — через
  `https://files.minecraftforge.net/.../meta` и NeoForge meta.
- Результат: json-файл версии, `FabricMC` и т.п.

### 3.5. Прямое скачивание модов
- Поиск `GET /search?query=...&facets=[["project_type:mod"]]`.
- Выбор версии мода, совместимой с лоадером и MC текущего инстанса.
- Скачивание primary файлов + разрешение зависимостей (`dependencies`).
- Складывание в `<instance>/mods/`.

### 3.6. Запуск игры
- Сборка classpath из libraries + client.jar.
- JSON версии (исправленный) с библиотеками.
- Автопоиск Java или скачивание (Adoptium API).

> Примечание: офлайн-запуск без входа в аккаунт — бесплатная версия с
> offline-сессией (имя + UUID). Полноценный вход в Microsoft — отдельный
> оверфлоу, можно добавить позже по желанию.

## 4. Архитектура

```
minecraft launcher/
├─ assets/            (сгенерированные ассеты: иконки, фоны, UI-элементы)
├─ electron/
│  ├─ main.js         (окно, IPC-мосты, обработчики)
│  └─ preload.js      (защищённое API для рендера)
├─ src/
│  ├─ index.html
│  ├─ styles.css     (токены дизайна: цвета, радиусы, тени)
│  └─ app.js         (рендер: навигация, карточки, события)
├─ core/             (логика в главном процессе: network, fs, instances)
│  ├─ mojang.js      (манифест + установка vanilla)
│  ├─ modrinth.js    (search/project/version + .mrpack)
│  ├─ loaders.js     (fabric/quilt/forge/neoforge)
│  ├─ install.js     (инстанс: создание, файловая система)
│  ├─ java.js        (поиск/скачивание JRE)
│  ├─ launch.js      (построение classpath, спавн java)
│  ├─ downloader.js  (прогресс, sha1, retry)
│  └─ state.js       (JSON состояние — профили, настройки)
├─ tests/            (юнит-тесты для core)
└─ package.json
```

## 6. Ассеты: промпт в `ASSET_PROMPT.md`

Отдельный файл с готовым промптом для генерации изображений:

## 7. Данные и API

- Mojang: `launchermeta.mojang.com` (манифест), `piston-meta.mojang.com`
  (version.json), `resources.download.minecraft.net` (ассеты).
- Modrinth (v2, API-ключи не нужны):
  - `GET /v2/search` — поиск проектов/модов/сборок;
  - `GET /v2/project/{id}` — информация;
  - `GET /v2/project/{id}/version` — версии (game_versions, loaders);
  - файлы: `files[].url`, хэши `files[].hashes` для проверки;
  - `.mrpack`: `modrinth.index.json` (formatVersion, files, dependencies, overrides).
- Loader-мета:
  - Fabric: `https://meta.fabricmc.net/v2/versions/loader/{mc}`
  - Quilt: `https://meta.quiltmc.org/v3/versions/loader/{mc}`
  - NeoForge: `https://maven.neoforged.net/...` + NeoForge meta
  - Forge: `https://files.minecraftforge.net/...`
- JRE: Adoptium API `https://api.adoptium.net/v3/assets/latest/...` (опционально).

## 8. Этапы реализации (milestones)

1. **Фундамент**: package.json, Electron main/preload, окно 1280×800,
   рендер-оболочка, стор-состояние, навигация.
2. **Дизайн**: токены палитры, сетка, карточки, ассеты из промпта, иконки.
3. **Инсталляция vanilla**: манифест → выбор версии → скачивание jar/libs/assets
   с прогрессом и sha1.
4. **Инстансы и инсталл модовых версий**: создание профиля + loaders
   (Fabric/Quilt в первую очередь, Forge/NeoForge — позже).
5. **Modrinth сборки**: поиск, карточка, установка `.mrpack` с зависимостями.
6. **Моды**: поиск, выбор версии по loaders+MC, скачивание + зависимости,
   менеджер модов в инстансе.
7. **Запуск**: сборка classpath, поиск/скачивание JRE, spawn java, логи.
8. **Тесты и упаковка**: юнит-тесты core, README, инструкция запуска.

## 9. Критерии приёмки

- Лаунчер запускается и показывает минималистичный зелёно-жёлтый UI.
- Выбранная vanilla-версия скачивается с прогрессом и sha1-проверкой.
- Сборка с Modrinth устанавливается (файлы + overrides + loader).
- Мод с Modrinth ставится прямо в инстанс с его зависимостями.
- Для Fabric-инстанса возможно собрать запуск на машине с установленной Java.

## 10. Риски

- Electron-бинарник (~100 МБ) — первый запуск дольше; при недоступности —
  эскиз UI как локальный HTML и логика, тестируемая без Electron.
- Без аккаунта Microsoft запуск в офлайн-режиме (как demo) — минимально
  жизнеспособно; онлайн-аутентификация — отдельная задача.
- Forge/NeoForge-инсталлеры сложнее — их ставим вторым приоритетом.
