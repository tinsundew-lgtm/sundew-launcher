# Ревью проекта LimeCraft (папка `imecraft`)

Дата: 2026-10-25 · Стек: Rust 2024, eframe/egui 0.37, reqwest (blocking) · Объём: ~3 500 строк в `src/` (`app.rs` 1 550, `core/install.rs` 800).

## Коротко

Архитектура разумная: ядро в `src/core/` отделено от UI, загрузки идут через `.part` с переименованием, SHA-1 проверяется, данные лежат в папке пользователя. Но **основные заявленные сценарии сейчас не работают**. Причины простые и чинятся быстро. Ядро я собрал отдельно и прогнал тесты и пробы на реальных JSON. Вот что подтвердилось запуском:

| Сценарий из README | Состояние | Причина |
|---|---|---|
| Vanilla: установка и запуск | Скорее всего запускается, **но без ассетов** (звуки, часть ресурсов) | П-1 |
| Fabric / Quilt | **Не устанавливается** (битые URL библиотек) и запускался бы без загрузчика | П-1, П-2 |
| Модпаки `.mrpack` | **Не устанавливаются вообще** (ошибка разбора индекса) | П-3 |
| Forge / NeoForge | **Не запустятся** | П-4 |
| Отмена установки | Кнопка есть, **не работает** | П-6 |

Сам Minecraft на вашей машине я не запускал. Утверждения про «не запустится» для Forge и про ассеты в vanilla основаны на чтении кода и пробах, а не на живом запуске.

Что проверено запуском (изолированная копия `core/`, Linux, свежие версии зависимостей без вашего `Cargo.lock`):
- `cargo test`: 7 прошли, **2 падают** (`main_class_forms`, `library_remote_formats`). Оба падения указывают на настоящие баги (П-1, П-2).
- Проба на реалистичном JSON версии 1.21.1: `main_class=None`, `asset_index=None`, `java_version=None`.
- Проба на профиле Fabric: `main_class=None`, URL библиотеки `https://maven.fabricmc.netnet/fabricmc/...`.
- Проба на индексе `.mrpack`: `missing field format_version`.
- Проба сборки команды запуска для профиля в стиле Forge: см. П-4.

## P0 — ломает основные функции

### П-1. Нет `rename_all = "camelCase"` у структур Mojang
`src/core/mojang.rs:38-67, 91-94` — `VersionJson`, `AssetIndex`, `JavaVersion`. В JSON от Mojang ключи `mainClass`, `assetIndex`, `inheritsFrom`, `javaVersion`, `majorVersion`, `totalSize`. Поля в Rust названы в snake_case, а переименования нет. Serde молча игнорирует незнакомые ключи, поэтому ошибок нет, а данных тоже нет.

Последствия:
- `asset_index` всегда `None`, поэтому `install_assets` (`install.rs:156`) не вызывается и **ассеты не скачиваются никогда**;
- `main_class` всегда `None`, и запуск откатывается на `net.minecraft.client.Main`. Для Fabric/Quilt нужен `KnotClient`, значит игра стартовала бы **без загрузчика**;
- `java_version` и `inherits_from` не заполняются (и нигде не используются, см. П-5, П-7).

Исправление: `#[serde(rename_all = "camelCase")]` на `VersionJson`, `AssetIndex`, `JavaVersion`.
Важно: `VersionJson` ещё и `Serialize`. `install.rs:84` пересохраняет версию через `to_string_pretty`. Это даёт **не настоящий** Mojang-JSON, без неизвестных полей и со snake_case-ключами. Лучше сохранять исходный текст ответа (`get_text` и разбор отдельно). Ранее сохранённые файлы у вас на диске придётся переустановить.

### П-2. Неверная сборка URL библиотек Fabric/Quilt
`src/core/mojang.rs:141-143`:
```rust
format!("{}{}", base.trim_end_matches('/'), path.display())
```
Между базой и путём нет `/`, а на Windows `display()` ещё и даёт обратные слэши. Получается `https://maven.fabricmc.netnet/fabricmc/...`. Так падает каждая библиотека любого профиля Fabric/Quilt.
Исправление: `format!("{}/{}", base.trim_end_matches('/'), path.to_string_lossy().replace('\\', "/"))`.

### П-3. `.mrpack` не разбирается
`src/core/modrinth.rs:75-83` — у `ModrinthIndex` те же проблемы: в индексе `formatVersion`, `versionId`. Проба подтвердила ошибку `missing field format_version`. Установка **любого** модпака падает. Исправление та же: `rename_all = "camelCase"` (у `IndexFile` добавить также опциональные `env` и `fileSize`).

### П-4. Forge / NeoForge не могут запуститься
Несколько независимых причин:
1. `install.rs:320-360` берёт из installer-джара только `version.json`. **Процессоры инсталлятора не выполняются** (патч клиента, генерация `*-client.jar`/mappings), поэтому ключевые jar-файлы не появятся. Библиотеки без URL молча пропускаются (`install.rs:125`).
2. `launch.rs:175-188` фильтрует аргументы игры: флаги `--...` отбрасываются, а **значения остаются**. Проба для Forge-профиля дала лишние позиционные аргументы `forgeclient 52.1.20 1.21.1`.
3. `launch.rs:139-156` берёт только строковые JVM-аргументы. Объекты с `rules` игнорируются, а у Forge/NeoForge нужен module path (`-p`, `--add-modules`) и свой bootstrap. Просто «все jar в classpath» тут не работает.
4. `-cp` добавляется дважды (свой и из JSON), ничего страшного, но нечисто.

### П-5. Профили загрузчиков не наследуют vanilla (`inheritsFrom`)
Профили Fabric/Quilt/Forge содержат только свою часть. Поля `assets`, `assetIndex`, `arguments` берутся из vanilla-JSON, но `launch.rs:98-128` читает **только** JSON профиля. Итог: `--assetIndex` падает на захардкоженное `"1.7.10"` (`launch.rs:128`), vanilla-аргументы теряются. Нужно слить профиль с родителем (как делают все лаунчеры) и вычислять classpath по списку библиотек, а не «все jar из папки».

### П-6. Отмена установки не работает
`InstallProgress.cancelled` объявлен (`install.rs:21,30`), но нигде не читается. Кнопка «Отмена» в UI (`app.rs:260`) только выставляет флаг. Для установки модпака и инсталлятора загрузчика вызывается `download_file_with_progress(..., None)`, то есть без отмены.

### П-7. Java подбирается без проверки версии
`launch.rs:8-52`: берётся первая найденная Java (JAVA_HOME, PATH, потом `read_dir` без сортировки). Для MC 1.20.5+ нужна Java 21, для 1.18+ — 17, для старых 8. `java_version` из JSON не парсится (П-1) и не используется, а скачивание JRE из PLAN.md не реализовано. Итог: «Игра запущена», а процесс сразу умирает с `UnsupportedClassVersionError`.

### П-8. Запуск: статус «успех» при мгновенном падении, лог-файл конфликтует с игрой
- `app.rs:650`: `_child` отбрасывается, выход процесса не отслеживается. Сообщение «Игра запущена» показывается даже если Java тут же упала.
- `launch.rs:213-222`: stdout/stderr пишутся в `logs/latest.log` — **тот же файл, что открывает сам Minecraft (log4j)**. Два писателя в одном файле; на Windows возможна блокировка. Пишите в `launcher.log`.
- `launch.rs:163`: `--accessToken=0` зашит, параметр `_access_token` игнорируется (для Microsoft-входа понадобится).

## P1 — безопасность и надёжность

### Безопасность
1. **Path traversal через `.mrpack`.** `install.rs:626`: `inst_dir.join("mines").join(&f.path)`. `f.path` берётся из индекса без проверки. `../../..` выходит из инстанса, а **абсолютный путь вообще заменяет базу** (`Path::join`). Вредоносный модпак может записать файл куда угодно (например, в автозагрузку). Нужно проверять: относительный путь, без `..`, без префикса диска, результат внутри папки инстанса.
2. **Распаковка zip.** `modrinth.rs:191`: проверка на `..` делится по `/`. На Windows имя вида `..\..\x` её обходит. Используйте `entry.enclosed_name()`. Файлы читаются целиком в память, лимитов на размер нет.
3. **Файлы модпака не проверяются хэшем.** `install.rs:641` скачивает через `download_file_with_progress` без проверки. Хэш сверяется только для уже лежащего файла. Индекс даёт `sha1`/`sha512`, а `file_sha512` в `download.rs:132` нигде не вызывается. README обещает проверку SHA-1.
4. **`env` игнорируется.** Серверные моды (`env.client = unsupported`) ставятся на клиент. Клиентские `client-overrides/` не применяются.
5. `launcher_state.json` хранит токены открытым текстом (пока поля пустые, но под Microsoft-вход нужно хранилище ОС).

### Корректность
6. **Зависимости модов без учёта версии и загрузчика.** `install.rs:731-733` берёт `versions.first()` — самую свежую версию зависимости для любой версии игры. Фильтров по `game_versions`/`loaders` нет, `version_id` из зависимости не используется. Плюс `app.rs:1159`: при ошибке фильтрованного запроса молча берутся **все** версии мода.
7. **Версия загрузчика из модпака игнорируется.** `install.rs:581-594` вычисляет `pack_loader`, но ставится «последний» загрузчик. Для Forge/NeoForge/Fabric версия из `dependencies` часто критична.
8. **Имя файла JSON профиля.** `install.rs:290-294` и `install.rs:519-525` могут разойтись, если `loader_version` уже задан. `install.rs:265` подставляет `"0.16.9"`, если ответ меты не разобран.
9. **Мастер называет инстанс именем версии** (`app.rs:785`). Создание Fabric 1.21.1 после Forge 1.21.1 **перезапишет** первый инстанс (то же имя, та же папка, `upsert` по имени). Заодно `sanitize` (`instance.rs:89`) склеивает разные имена (`a/b` и `a_b`).
10. **Модпак: полусозданный инстанс.** `app.rs:941` записывает инстанс `game_version: "latest"` в состояние до установки. При ошибке он остаётся в списке навсегда.
11. **Состояние.** `instance.rs:63-76`: запись не атомарная, а при ошибке разбора `unwrap_or_default()` молча подставляет пустое состояние. Сбой во время записи = потеря всех инстансов при следующем сохранении. Нужны запись во временный файл + rename и резервная копия при ошибке разбора.
12. **Нет таймаутов** (`install.rs:36-42`): зависший сервер подвесит установку навсегда. Нет ретраев (в `README` и в doc-комментарии `download.rs` они заявлены).
13. **Падение рабочего потока.** `app.rs:43-45`: если поток паникует, слот остаётся `None`, интерфейс крутит спиннер бесконечно. Оберните в `catch_unwind` или передавайте `Err`.
14. **Удаление сборки** (`app.rs:569-573`) убирает запись из списка, но **файлы остаются** на диске (гигабайты). Подтверждения нет.
15. **Старые версии (≤1.12, LWJGL 2).** Нативные jar только скачиваются в `libraries` (`install.rs:106-120`) и не распаковываются в `java.library.path`. Комментарий предполагает самораспаковку LWJGL 3. Для старых версий это скорее всего не сработает.
16. Ассеты качаются **последовательно**, по одному запросу на файл (`install.rs:223-229`; ~3 000+ файлов на версию). Нужен пул потоков. Прогресс при переходе между этапами сбрасывается.
17. `app.rs:276`: `request_repaint()` на каждом кадре — постоянная нагрузка на CPU/GPU даже в простое. Достаточно перерисовки при активных задачах (`request_repaint_after`).
18. `app.rs:1314`: `ram_mb` принимается без проверок (`parse().unwrap_or(4096)`), ник — без валидации; введённый ник применяется только после «Сохранить».
19. Аккаунт «Microsoft (скоро)» выбираем в списке и сохраняется, а запуск всё равно офлайновый.

## P2 — качество, гигиена, документация

### Ассеты (проверено)
Файлы названы не тем, чем являются. Все — JPEG, а размеры огромные:

| Файл | Заявлено | По факту |
|---|---|---|
| `badge-256.jpg` | 256×256 | JPEG 2048×2048, 1.3 МБ |
| `play-256.jpg` | 256×256 | JPEG 2048×2048 |
| `modpack-256.png` | PNG 256 | **JPEG** 2048×2048 |
| `empty-state.png` | прозрачный PNG | **JPEG** 2400×1792, без прозрачности |
| `favicon-64.ico` | ICO 64×64 | **JPEG** 2048×2048 (1.7 МБ) |
| `hero-1920x1080.jpg` | 1920×1080 | 2752×1536 |

Работает только потому, что `image::load_from_memory` определяет формат по содержимому. Последствия: ~9 МБ вшито в бинарник; на старте синхронно декодируется 6 изображений (~100 МБ текстур); иконка окна 2048² RGBA; «прозрачные» иконки на самом деле с фоном. `hero`, `play_icon` и `paint_cover` нигде не используются, `Gemini_Generated_Image_…jpg` — неиспользуемый исходник. Нужно: уменьшить до реальных размеров, сделать настоящие PNG/ICO, убрать лишнее.

### Сборка и зависимости
- `log`, `env_logger`, `egui_extras` в `Cargo.toml` не используются; логирование нигде не инициализировано. Пустая секция `[build-dependencies]`. Нет `license`, `description`, `rust-version`.
- `main.rs:28-42`: отладочная запись `limecraft_start.log` и `limecraft_panic.log` в `env!("CARGO_MANIFEST_DIR")` — путь вашей машины, зашитый при компиляции. В релизе он не существует. Лучше писать в папку данных через `log`.
- `app.rs:158-164`: паника при недоступной папке данных вместо диалога с ошибкой.
- `release`: `opt-level = 2`, без `strip`/`lto` — при ~9 МБ вшитых картинок бинарник раздут.

### Тесты
Только юнит-тесты на чистые функции в `core/`, и 2 из 9 красные. Нет тестов на разбор реальных JSON (ровно то, что ломается), на сборку команды запуска, на защиту от path traversal. Нет CI (`.github/`). Тест `account.rs:94-116` проверяет только стабильность и формат, без эталонного значения.

### Репозиторий
- Remote: `github.com/tinsundew-lgtm/sundew-launcher`, проект называется LimeCraft, папка `imecraft`. Три разных имени.
- В корне лежит посторонний мусор, он **не отслеживается** (файлы новее последнего коммита) и не в `.gitignore`: `.superpowers-tmp/` (клон стороннего репозитория со своим `.git`, 253 файла), `asar_list.txt` (1.5 МБ), `extract-asar.js`, `skill-fs-readme.md` (README постороннего пакета). Риск попасть в коммит при `git add -A`. Удалить или добавить в `.gitignore`. Выполните `git status`, чтобы убедиться.
- Две почти одинаковые временные папки `.build-tmp` и `.buildtmp` (обе в `.gitignore`).
- В `.gitignore` остались правила `кот/`, `кота/`.

### Документация
- `PLAN.md` описывает **Electron** (стек, архитектура, этапы), а код на Rust/eframe. Заголовок говорит «РЕАЛИЗОВАН», тело противоречит. Либо переписать, либо пометить как историческое.
- README: в таблице «Что внутри src/» нет `app.rs` (самый большой файл); пути `minecraft launcher/` и `C:\tinSundew\minecraft launcher` не совпадают с реальной папкой; «Возможности» заявляют работающими то, что описано в П-1…П-6; в `app.rs:1002` ссылка на вкладку «Главная», которой нет.
- `assets/MANIFEST.md` описывает размеры и форматы, которых нет (см. таблицу выше).
- Дублирование UI: мастер на вкладке «Сборки» и отдельное окно «Создать инстанс» делают одно и то же двумя копиями кода. «Ресурспаки», «Шейдеры», «Настройки сборки» — заглушки. Менеджера модов (включить/выключить/удалить), обещанного в плане, нет.

## Что сделано хорошо
- Чёткое разделение `core/` и UI; тяжёлая работа на фоновых потоках, UI не блокируется.
- Скачивание в `.part` + rename, повторное использование файла с совпавшим SHA-1.
- Данные в пользовательской папке (`dirs::data_dir`), а не рядом с exe; `rustls` без OpenSSL.
- Офлайн-UUID по алгоритму Minecraft (MD5, версия 3) реализован верно.
- Попытка защиты от zip-slip уже есть (надо довести).
- `Cargo.lock` закоммичен, тема вынесена в токены.

## План исправлений (по убыванию отдачи)

2. **~полдня.** П-5 и П-7: слияние `inheritsFrom`, classpath по списку библиотек с учётом правил, подбор Java по `javaVersion`, разбор аргументов с `rules` и подстановкой плейсхолдеров. Это откроет vanilla и Fabric/Quilt.
3. **Безопасность:** валидация путей в `.mrpack` (пункты 1–2 раздела «Безопасность»), проверка хэшей, `env`.
4. **Надёжность:** таймауты, отмена, атомарное сохранение состояния, имена инстансов, `catch_unwind`, лог игры отдельным файлом, отслеживание завершения процесса.
5. **Forge/NeoForge** — отдельная задача: либо выполнять процессоры инсталлятора (запуск его через `java -jar … --installClient`), либо честно пометить «не поддерживается».
6. **Гигиена:** ассеты, лишние зависимости, мусор в корне, README/PLAN/MANIFEST.
